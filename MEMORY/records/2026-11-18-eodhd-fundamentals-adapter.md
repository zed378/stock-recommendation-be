# EODHD adapter for IDX fundamentals (owner's decision, 2026-11-18)

Context: the IDX adapter is refused with 403 by the site's bot management from the VM's address (see `2026-11-18-idx-403-profile-trial.md`). The owner rejected workarounds and chose a licensed source with an API: **EODHD for fundamentals**; the daily trading summary with foreign flow (no public official API found) is left as it is, still trying and failing, by the owner's choice.

What was added (code only, **not deployed, no key, EODHD never called**): `src/aidss/plugins/adapters/market_eodhd.py` (adapter `eodhd`, fundamentals only, for the composite provider), settings `eodhd_api_key` (blank is unset, redacted in logs) and `eodhd_symbol_suffix` (`.JK`), pass-through `AIDSS_EODHD_API_KEY` in both compose files, env examples and README, 12 tests with canned responses (`tests/test_market_eodhd.py`), and a live test skipped without a key (`tests/test_eodhd_live.py`).

Behaviour worth knowing: metrics reuse the shared vocabulary and carry the most recent reported quarter as their period; opinions (`WallStreetTargetPrice`) and price statistics (52-week, moving averages) are deliberately not stored; a non-IDR report is refused, not mixed; 404 or an empty body means no coverage (empty list); 401/403 are permanent, 402 (allowance used up), 429 and 5xx are retryable; the token is removed from every error message because it travels in the URL.

NOT verified: everything about the real service. The shapes come from EODHD's fundamentals page (endpoint form, `api_token` query parameter, section and field names, "10 calls per request"); the page documents neither the answer for an unknown ticker or bad token nor the account endpoint used by `health_check`, and it does not list a Jakarta ticker, so coverage and field names for `.JK` must be confirmed with the live test once a key exists. Pricing (a plan with the Fundamentals API, about USD 59.99 per month on EODHD's listing, personal use) and the licence terms are the owner's to read and accept.

To use it: take a plan with the Fundamentals API; put `AIDSS_EODHD_API_KEY` in `~/stocks/.env` (`infra:infra 600`, never in chat); set `AIDSS_COMPOSITE_FUNDAMENTALS_PROVIDER=eodhd` and a `AIDSS_FUNDAMENTALS_DAILY_QUOTA` from the plan (default 25 is Alpha Vantage's; one EODHD request costs 10 of the plan's calls); build and deploy a new api image; add the pass-through line to the host compose file; recreate api and worker with `--no-deps`; run `pytest -m network tests/test_eodhd_live.py` first.
