# First deployment of the Trader to the VM (running, HALTED, no exchange)

**Date:** 2026-11-15
**Task:** deployment; verifies part of T1-01, T1-03, T1-07
**Author:** Claude (AI agent), working with the project owner

---

## Hook

The Trader runs on the VM for the first time, next to the analysis stack in the `stocks` Compose project. It holds
the lease, serves its operator API through the front end's `/trader/` proxy, and sits `HALTED` with no exchange URL
and no credential, so it can trade nothing. This is also the first run on a real PostgreSQL.

## Verified On Real PostgreSQL For The First Time

- All six migrations apply, and the version table works after one fix: the `trading` schema must exist before
  Alembic writes its version table (`alembic_trader/env.py`, commit `5be7875`). The first attempt failed on it.
- `tests/trader/test_privileges_postgres.py` passed (3 tests) against a throwaway database on the same server
  (the `aidss` database was not used, because that test appends to the append-only audit log). The scratch
  database was dropped afterwards.
- The Trader starts, takes the lease, writes its heartbeat, and its container healthcheck passes; the initial
  state row reads `HALTED: initial state: awaiting the owner's resume`.
- The front end's nginx reaches the Trader: `GET /trader/v1/status` without a token answers 401 from the Trader.

## Not Verified

- No authenticated request was made, no screen was opened in a browser, and nothing was tried with a real user.
- No exchange was contacted. The exchange URLs are unset, so no key can be stored yet (a key is tested before it is
  stored).
- Column-level grants were exercised by only the three existing privilege tests, not by every table.
- Migration 0005 and 0006 grants, and the running role's behaviour under load, are untested on PostgreSQL beyond
  the above.

## Open Findings On The Host

- PostgreSQL is published on the host's port 5432 and its superuser password equals its username. Anything on the
  network can read and change every table, including the Trader's. This must be fixed before a key is stored
  (restrict the port, rotate the password, and move the analysis API to a limited role; see the backlog).
- The database and the server are the same host; the dump above is on the same disk.
- The password used to deploy was shared in chat earlier and should be rotated.
